This is a source-backed inventory, not a claim that VideoGen has implemented these features.

are product boundaries and guides. Moving files or writing guides does not consolidate code.

random seeds; ordered unique multiple picks; prompt composition; option/preset writes; SDK assets;
draft gate; gateway prepare; job submit; actionable workflow/missing-model errors; raw SSE parsing
and reconnects. It requires COMFY_BASE_URL only when a Runner is constructed for backend work.

starting/queued/running/succeeded/failed/canceled/expired/lost states; atomic metadata writes;
polling plus SSE previews/queue/progress; monotonic progress capped below100% before completion;
retry transient observation failures with backoff; capture node errors/timings; download declared
media outputs; extension correction for MP4 reported as image; recent-job resume after restart;
cancel/delete including submit races; constrained result paths; optional visitor ownership.
Observation retry is not a guaranteed idempotent task submission or durable distributed retry queue.
F/server/guard.ts: optional shared demo passcode; keyed-hash HttpOnly/Secure cookie; random visitor
IDs; persisted UTC daily run cap; active-run cap; loopback Host checks and cross-site write rejection.
This is reference demo protection, not VideoGen accounts, RBAC, tenant security or billing.
F/server/flags.ts: validated mediocre-example marks, optional note/timestamp, disk persistence;
gallery-option keys and stale-mark pruning. Hosted server disables mark writes.
F/server/cli.ts: validate; list apps; run app with --set/--file/--preset/--out/--draft;
wait for success and save declared outputs. Run commands can invoke real backend compute.
F/server/server.ts: HTTP catalog; workflow download; multipart async run submission; history list,
detail, files/byte ranges, previews, cancellation and deletion; GPU status/wake; flags; local-only
raw job/output routes; static UI. Backend access is lazy, so catalog browsing needs no GPU.
Warm-state tracking is a recent-contact heuristic; device data is best effort, not GPU readiness proof.

8. COMFYUI ENGINE FEATURES AND BOUNDARIES (STATIC SOURCE INSPECTION)
C/pyproject.toml declares 0.45.0. This is not proof of upstream authenticity or compatibility with
FreeField's pinned e3bee7ff... engine; its manifests describe 0.42.0. Keep the snapshots separate.
C/main.py: argument/startup configuration, extra model paths, database initialization, prompt
worker and optional manager/custom-node prestartup hooks. Extension startup executes Python code;
importing a workflow is not permission to install arbitrary untrusted custom nodes.
C/execution.py: validate_prompt/validate_inputs, node execution and output merging, change-aware
caches, PromptExecutor and PromptQueue; interruption, errors and completion feed the server.
C/comfy_execution/graph.py: DynamicPrompt, dependency/topological ordering, cycles and node-input
errors; caching.py: signature/ID, hierarchical, LRU and RAM-pressure caches. Not an owned job ledger.
C/nodes.py: CLIP text conditioning/combine/area/mask/time controls; VAE encode/decode/tiled/inpaint;
checkpoint/diffusers/UNet/CLIP/vision/VAE/LoRA/ControlNet/style loaders and application; latent
batch/resize/composite/transform; KSampler; image load/save/preview and built-in node registration.
C/comfy/sd.py: CLIP/VAE wrappers, text-encoder detection, LoRA patches, state/checkpoint/diffusion
model loading and checkpoint save. comfy/model_detection.py/model_base.py and ldm/ carry model
family implementations; presence of family code is not proof that any checkpoint runs here.
C/comfy/sample.py and samplers.py: seeded noise, latent-channel setup, conditioning, masks, CFG,
sigma schedulers and sampling implementations; comfy/model_management.py: device/dtype selection,
VRAM accounting, GPU loading, offload, memory pressure and model cleanup/interruption.
